⏺ Yes, venv = virtual environment. Think of it like this:

  ▎ Each project gets its own little box. Flask goes inside that box. Another 
  project gets a different box with different stuff. They don't mix.

  Without venv, everything installs globally on your Mac and projects can
  conflict.

  ---
  The files/folders explained:

  ┌──────────────────┬───────────────────────────────────────────────────────┐
  │      Thing       │                      What it is                       │
  ├──────────────────┼───────────────────────────────────────────────────────┤
  │ venv/            │ The box (folder containing your isolated Python +     │
  │                  │ packages)                                             │
  ├──────────────────┼───────────────────────────────────────────────────────┤
  │ venv/bin/        │ Executables inside the box (python, pip, activate     │
  │                  │ script)                                               │
  ├──────────────────┼───────────────────────────────────────────────────────┤
  │ activate         │ A script that tells your terminal "use THIS box from  │
  │                  │ now on"                                               │
  ├──────────────────┼───────────────────────────────────────────────────────┤
  │ requirements.txt │ A shopping list of packages the project needs         │
  └──────────────────┴───────────────────────────────────────────────────────┘

  ---
  For every new project, do this once:

  cd ~/Desktop/your-project-folder   # go into the project
  python3 -m venv venv               # create the box
  source venv/bin/activate           # step inside the box
  pip install flask                  # install what you need

  Every time you open a new terminal to work on that project:

  cd ~/Desktop/your-project-folder
  source venv/bin/activate
  python3 app.py

  You'll see (venv) in your prompt — that means you're inside the box.

  ---
  The golden rule:
  - source venv/bin/activate first — then everything just works
  - No (venv) in your prompt = not activated = Flask not found

  Does that make sense?

❯ i shoudld install requirmements too right? pip instal requieremets?           

⏺ Yes! The full sequence is:

  cd ~/Desktop/your-project-folder
  python3 -m venv venv
  source venv/bin/activate
  pip install -r requirements.txt
  python3 app.py

  pip install -r requirements.txt reads the shopping list and installs
  everything at once — better than installing one by one.

  When there's no requirements.txt (you're starting fresh), install manually:
  pip install flask

  Then save your shopping list for next time:
  pip freeze > requirements.txt

⏺ Here's the full structure explained:

  expense-tracker/
  │
  ├── app.py                  ← The brain. All routes/URLs defined here
  │
  ├── database/
  │   ├── __init__.py         ← Makes this folder a Python package (empty)
  │   └── db.py               ← Database functions (empty — Step 1 to build)
  │
  ├── templates/              ← HTML pages Flask renders
  │   ├── base.html           ← Master layout (navbar + footer shared by all
  pages)
  │   ├── landing.html        ← Homepage — extends base.html
  │   ├── register.html       ← Register page
  │   └── login.html          ← Login page
  │
  ├── static/                 ← Files sent directly to the browser
  │   ├── css/style.css       ← All styling for the app
  │   └── js/main.js          ← JavaScript (empty — to be built)
  │
  ├── requirements.txt        ← Shopping list of Python packages
  └── venv/                   ← Your virtual environment (don't touch)

  How they connect:

  - Browser visits / → app.py handles it → renders landing.html → which extends
  base.html → styled by style.css
  - base.html is the skeleton — every page plugs into it so the navbar and
  footer appear everywhere automatically
  - database/db.py will connect to SQLite once you build it

  The pattern is: URL → app.py → template → browser
